# 🔥 خطة «الجمرة التي لا تنطفئ» — EMBER

> الهدف: تحويل المستودع من **مشروع يشتعل عند الدفع** إلى **كتلة جمر تتوهّج ذاتيًا**:
> تُشعل نفسها، تتغذّى على دليلها، لا تسقط بنقطة فشل واحدة، تُصلح نفسها، وتُظهر حرارتها للعالم.
> كل رقم في هذه الخطة مقيس بأمر، لا مكتوب بوعد.

| # | السبب المقيس | الدليل (أمر) | النتيجة الحالية |
|---|---|---|---|
| 1 | **لا اشتعال ذاتي** | `grep -rn "schedule\|cron" .github/workflows/` | **صفر** — لا يوجد أي جدولة |
| 2 | **الاحتراق مرتبط بدفعك** | `ls .github/workflows/` | `ci.yml` + `pages.yml` فقط، كلاهما `push`/`workflow_dispatch` |

> «حجر ساخن»، لا «جمرة».

## 2️⃣ التعريف الهندسي لـ«لا ينطفئ» — ٦ شروط قابلة للقياس

| الشرط | معنى عملي | يُقاس بـ |
|---|---|---|
| **الاشتعال الذاتي** | يعمل بلا إنسان | `gh run list --workflow ember.yml` فيه تشغيلات لم تُطلقها يدويًا |
| **التغذية الذاتية** | كل دورة تنتج وقودًا للدورة التالية | عدد الذكريات + `bench.json` + `status.json` تتراكم |
| **تعدّد الجمرات** | لا نقطة فشل واحدة | ≥ 3 مسارات نشر/تشغيل مستقلّة، كل منها `200` |
| **المناعة** | الفشل يُعلن ويُصلح | فشل مُصطنع ⇒ issue تلقائي خلال نبضة + عودة تلقائية |
| **المرئية** | الحرارة تُرى من الخارج | شارات حيّة + `STATUS.md` مُعاد توليده تلقائيًا |
| **الاسترجاع** | يبقى قابلًا للإشعال على أي آلة | استرجاع كامل في ≤ 10 دقائق بلا اعتماديات |

## 3️⃣ المعمارية: النبضة (Beat)

```
                 ┌──────────── كل 6 ساعات (cron) ────────────┐
                 │            ember.yml (نبضة)               │
                 └───────────────┬──────────────────────────┘
                                 │
   ┌──────────────┬──────────────┼───────────────┬────────────────┐
   ▼              ▼              ▼               ▼                ▼
تشغيل حقيقي   smoke 13/13    إعادة توليد     تحديث status.json   نبضة كوميت
(Live Agent)   (HTTP)        كل الأرقام      + STATUS.md         (يمنع تعطيل
   │              │           (generate_*)      │                الجدولة)
   ▼              ▼              │              ▼                │
 ذاكرة +أثر    PASS/FAIL        أرقام صادقة   Pages حيّة          ▼
                                        │                    بـ heartbeat
                                        ▼
                                 فشل؟ ⇒ issue + rerun + تصعيد
```

**مبدأ حاكم:** النبضة لا تدّعي النجاح. إن فشل أي فحص، تُعلن الجمرة «خامدة مؤقتًا» بصدق
(`status: degraded`) وتفتح issue، بدل أن تُخفي الفشل.

## 4️⃣ المراحل — بالترتيب حسب الأهمية

### 🔴 المرحلة 0 — الأكسجين: الاشتعال الذاتي (أهم شيء، بلا اعتماد على أحد)
**المخرج:** `.github/workflows/ember.yml` — `schedule: cron "0 */6 * * *"` + `workflow_dispatch`.

```yaml
name: Ember beat
on:
  schedule: [{cron: "0 */6 * * *"}]
  workflow_dispatch:
concurrency: {group: ember, cancel-in-progress: false}
jobs:
  beat:
    runs-on: ubuntu-latest
    permissions: {contents: write, issues: write, actions: write}
    steps:
      - uses: actions/checkout@11d5960a326750d5838078e36cf38b85af677262   # مثبّت
      - uses: actions/setup-python@a26af69be951a213d495a4c3e4e4022e16d87065  # مثبّت
        with: {python-version: "3.11"}
      - name: Boot both servers, run the real smoke
        run: |
          python live-agent/server.py --port 8090 --host 127.0.0.1 & \
          python command-hud/server.py --port 8091 --host 127.0.0.1 & \
          for i in $(seq 1 20); do curl -sf localhost:8090/api/health >/dev/null && break; sleep 1; done
          python scripts/runtime_smoke.py
      - name: Publish heat (status.json + STATUS.md + heartbeat commit)
        if: always()
        run: python scripts/ember_beat.py --status-file website/status.json
```

> **تحديث Phase 2 (2026-11-19):** هذا المقطع التاريخي لا يهيّئ بيانات اعتماد API،
> لذلك لا يصلح للتشغيل كما هو بعد اعتماد سياسة الإغلاق الافتراضي. الـworkflow الحالي
> `.github/workflows/ember.yml` ينشئ رموزًا عشوائية مؤقتة لكل job، ويشارك سر القراءة
> مع smoke/heartbeat عبر بيئة الـjob؛ لا تُستخدم أسرار استضافة ولا تُطبع القيم.

**معيار القبول (مقيس):**
- `gh workflow list` يُظهر `Ember beat` بحالة `active`.
- `gh run list --workflow ember.yml --limit 3` ⇒ تشغيلات بلا `actor` يدوي.
- `gh api repos/…/contents/website/status.json` ⇒ `beats` يزيد بين نبضتين.
**التكلفة:** صفر (مستودع عام = دقائق غير محدودة) · **يحتاجك؟** لا.

> ⚠️ **قيد حقيقي (لا يُخفى):** GitHub يعطّل جدولة المستودعات العامة بعد **60 يومًا بلا نشاط**.
> لذلك النبضة تدفع كوميتًا صغيرًا إلى فرع `heartbeat` — الكوميت نفسه هو ما يُبقي اللهب مشتعلًا.

## 6️⃣ مؤشر الحرارة (Heat Index) — كيف نعرف أنها ما زالت جمرة؟

```
HEAT = 0.4×(نبضات ناجحة/آخر 7 أيام) + 0.2×(1 − أطول فجوة/24س) +
       0.2×(ذكريات متراكمة/100) + 0.2×(مسارات نشر حيّة/3)
```
- **≥ 0.8** = جمرة مشتعلة · **0.5–0.8** = ساخنة بلا لهب · **< 0.5** = تنطفئ.
- يُحسب في `ember_beat.py` ويُنشر في `status.json` — لا تقدير يدوي.
