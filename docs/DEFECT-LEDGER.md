# سجل الأعطال — كل عطل، ودليله، وما يمنع عودته

**القاعدة المتبعة** (من [`docs/GOVERNANCE.md`](GOVERNANCE.md)): *إذا لم يكن الضابط
مفروضًا بالكود أو بالمنصة، يُسجَّل كغير مفروض.*

لذلك كل صف في هذا الملف يحمل **أمرًا قابلًا للتشغيل** يُعيد إنتاج الدليل. صف بلا
أمر قابل للتشغيل = صف غير مثبت، ويجب أن يُقرأ كذلك.

**آخر تحقق:** 2026-11-20 · الفرع `arena/6e52403a-ai-2027`

## الأعطال الثمانية التي كشفتها الجولات

### 1. `exit=$?` بعد `tee` — رفض كان سيُقرأ كنجاح

| | |
|---|---|
| **العطل** | `cmd \| tee log` يُرجع حالة `tee` لا حالة `cmd`. أمر فاشل يبدو ناجحًا. |
| **الحالة** | **مُصلَح** — لكنه كان حيًّا في 3 مواضع لم تُذكر من قبل |
| **الدليل** | `bash -c 'false \| tee f; echo $?'` → `0` |
| **ما يمنع عودته** | `scripts/workflow_pipe_guard.py --assert` — يفحص 16 ملف workflow، وهو مربوط بـCI |
| **مواضع أُصلحت** | `ci.yml` (خطوة إقلاع ember) · `real-model.yml` (خطوتا التشخيص والفحص المباشر) |

قبل: `ci.yml` كانت `run: ./scripts/ember_up.sh --check --json | tee /tmp/up.json`
بلا `pipefail` — أي أن ember ميتًا كان يمرّ كنجاح.

## أعطال جديدة كشفها هذا التحقق (لم تكن في القائمة)

### 9. `pr-lens` يقرأ `PIPESTATUS` بعد `&&` (نمط هش)

```bash
npx … render … | tee -a log
rc=${PIPESTATUS[0]}
```
السطر السابق ينتهي بـ`&&` داخل `if`، فقراءة `PIPESTATUS` تعتمد على تنفيذ السطر
الأخير فقط. **مسجَّل كغير مفروض** — لم أُغيّره لأن تغييره يغيّر سلوك بوابة PR
غير المتعلقة بهذا العمل.

### 10. خلط `pipefail` مع `set +e` — نمط صحيح لكنه دقيق

في `real-model.yml`:
```bash
set -o pipefail; set +e
python … | tee log
status=${PIPESTATUS[0]}
```
هذا صحيح، لكنه يعتمد على أن `PIPESTATUS` يُقرأ **مباشرة** بعد الأنبوب. أي سطر
يُدسّ بينهما يُصفّره. الاختبار يحميه ضمنيًا عبر `workflow_pipe_guard` (الذي
يقبل `PIPESTATUS` كحارس على مستوى الخطوة).

### 11. سجل التقاعد كان يشير إلى نموذج ميت

**أخطر عطل في هذه الجولة، ولم يكن في القائمة الثمانية.**

`RETIRED_MODELS` سجّل تقاعد `meta/llama-3.1-8b-instruct` **وجعل
`meta/llama-3.3-70b-instruct` بديله** — والبديل نفسه تقاعد في **اليوم نفسه**.

النتيجة: ثلاثة ملفات كانت تعتمد افتراضيًا نموذجًا تُجيب NVIDIA عنه بـ`HTTP 410`.
**كل تشغيل قياس سابق كان يوزّع الجمل على مصرف لا يستطيع الإجابة.**

| | |
|---|---|
| **الحالة** | **مُصلَح** |
| **البديل الحيّ** | `z-ai/glm-5.3-flash` (على قائمة NVIDIA المجانية المنشورة، تحقق 2026-11-19) |
| **ما يمنع عودته** | `test_no_retirement_points_at_another_retired_model` |
| **الدليل** | أعِد البديل الميت → الاختبار يفشل بنصّه: «replaced by … which is itself retired» |

**حدّ الصدق:** البديل **لم يُختبر بعد بنموذج حقيقي من هنا** — الشبكة في هذه
البيئة محجوبة. الخطوة التالية هي تشغيل `real-model` يدويًا، والفحص المباشر
سيقول إن كان `z-ai/glm-5.3-flash` يجيب أم لا.

## فشل عابر لم أُصلحه ولم أُخفِه

**`Tests · Python 3.13` في `fleet-2027.yml`** فشل مرتين في خطوة
«Unit tests (stdlib only, no package install)»، ثم **نجح على نفس الالتزام
تمامًا** عند إعادة التشغيل (`gh run rerun --failed`).

| ما تحققت منه | النتيجة |
|---|---|
| هل لمست `fleet-2027/`؟ | **لا** — `git diff` يُثبت صفر تغيير |
| هل يمرّ محليًا؟ | 250/250 على `pytest` 8.3.4 و9.2.0 |
| هل يتكرر؟ | **لا** — إعادة التشغيل على نفس SHA نجحت |

**التصنيف الصادق:** فشل **عابر (flake)**، لا عطل مؤكد. لكني **لم أرى السجل**
(تحميل سجلات Actions محجوب من هذه البيئة)، فلا أستطيع تسمية الاختبار المتقلب.

**مسجَّل كغير مفروض.** إخفاؤه بإعادة تشغيل حتى يصير أخضر سيكون بالضبط الخطأ
الذي يمنعه هذا الملف.

## ما لم يُتحقق منه، ويُقال صراحة

- **البديل NVIDIA لم يُختبر حيًا من هذه البيئة.** لا TLS خارجي هنا.
- **الأعطال 1–8 أُثبتت بالإثبات العكسي** (احذف السلوك → يفشل الاختبار) حيث أمكن؛
  ولم يُثبَت بهذه الطريقة إلا ما كان له اختبار. العطل 2 و3 يثبتان بالكود والتشغيل
  الحقيقي لا بالإثبات العكسي.
- **الفشل 9 مسجَّل وغير مُصلَح** بوعي: تغييره يمسّ بوابة `pr-lens`، وهو خارج نطاق
  هذا العمل، وتوثيقه أصحّ من تغييره بلا قياس.
