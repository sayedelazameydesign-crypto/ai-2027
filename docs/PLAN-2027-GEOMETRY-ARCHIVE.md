## 4. المرحلة C — الطبقة 4 (تنفيذ/تحويل/تحرير)

`coverage = {compile: 0, patch: 1, ...}` اليوم — **`compile` صفر**، و`patch` معلن بلا اختبار تلف.

### C1. عقد التحرير الآمن
| القاعدة | المعيار |
|---|---|
| لا كتابة في المكان | الأصل يُفتح `"rb"` فقط؛ الناتج `<file>.new` |
| الأصل ثابت | `sha256` قبل == بعد |
| الفرق مرئي | unified diff بعدد أسطر `+`/`-` |
| فشل بلا أثر | patch فاشل ⇒ **لا** `.new` |

### C2. `compile` من 0 إلى 1
أول قدرة حقيقية: **CSV → parquet** (جدولي، بلا مكتبة) أو **STEP → STL**.
| القبول | الرقم |
|---|---|
| `coverage['compile']` | **≥ 1** |
| تحويل ناجح | `sales.csv 1,024 B → sales.parquet 718 B` |
| تحويل فاشل | سبب صريح، **لا ملف ناتج** |

### C3. `patch` مُثبَت
`coverage = {patch: 1}` بلا اختبار = رقم غير مُثبَت.
| القبول | الرقم |
|---|---|
| تعديل سطر | diff صحيح + `sha256` الأصل ثابت + `.new` مختلف |
| `coverage['patch']` | **≥ 2** |

**بوابة C:** `{compile:≥1, inspect:8, patch:≥2, query:1, render:3, slice:≥5}`.

## 11. OLE: إعادة البناء، عقد القراءة، والبوابة النهائية

### ما يُقرأ وما لا يُقرأ

`ole.py` يقرأ رأس CFB، وجدول FAT/DIFAT وسلسلة الدليل فقط؛ لا يفسّر stream payloads ولا macros ولا نص المستند. التنفيذ الإنتاجي (`read_ole_handle`) ينتقل إلى القطاعات المطلوبة بـ`seek`، ولا يقرأ بادئة الملف على أنها payload. التحقق يحسب SHA-256 مستقلًا على الملف بكتل 1 MiB للـlineage، ويصرّح أن ذلك hash لا تفسير للـpayload.

| الحماية | حدّ/اختبار القبول |
|---|---|
| سلاسل FAT/DIFAT والدليل | loop guard؛ FAT **128** قطاعًا كحد أقصى، DIFAT **128**، والدليل **1,024** قطاعًا أو **512 KiB** أيهما أسبق |
| sector geometry | CFB v3/512 B وv4/4,096 B؛ إزاحة v4 صحيحة |
| FAT | IDs صريحة غير متجاورة؛ اختبار القطاعين 1 و3 |
| DIFAT | اختبار FAT من 110 قطاعات (109 inline + امتداد DIFAT)، واختبار loop |
| تعريف النوع من البنية | `WordDocument` → `doc`; `Workbook` **أو** `Book` → `xls`; PowerPoint/MSG/Visio/encrypted stream لكل منها اختبار |
| فشل جزئي | بيانات الدليل المستخرجة تبقى قابلة للعرض؛ السلسلة الناقصة/المعطوبة لا تمر من validation |
| I/O payload | spy على handle لملف يحوي قطاع payload: القراءة اقتصرت على header + FAT + directory؛ لم يتقاطع أي range مع payload |
| اعتماديات | stdlib فقط؛ لا parser إضافي ولا كلفة تشغيل |

### قياس القارئ

- `tests/test_ole.py`: **67/67**؛ تغطية `ole.py`: **97.93%**.
- وصف ملف OLE بحمولة **8 MiB**: **0.17 ms متوسطًا** على 10 مرات؛ لم يقرأ الوصف payload.
- 8 أشكال document: Word، BIFF5، BIFF8، PowerPoint، MSG، Visio، encrypted، unknown؛ مع v4، دليل متعدد القطاعات، FAT متقطع، وDIFAT ممتد.
- الثابت: OLE يعلن `inspect` فقط؛ لا `slice` مزعوم لأن stream bytes لا تُقرأ.
- `describe_file("misleading.doc")` مع stream `Workbook` أعاد `kind=xls`؛ البنية الداخلية تتغلب على الامتداد. و`verify_file(..., kind="doc")` على الملف نفسه رُفض لأن الدليل يقول `xls`.
- ملف Word سليم: `valid` **ضمن نطاق header/FAT/DIFAT/directory** → تسليم `native (ole)`؛ stream payloads لا تُعلن validated.
- تغطية الـadapter: `inspect: 10`، ومصفوفة العمليات النهائية موثقة أعلاه.

### الحالة بعد الدمج

A، B، C، D1–D3 أُغلقت بأرقامها في التزامات #136–#138. دُمج قارئ OLE وتوابعه إلى `main` عبر PR #139 (`4be25ae`).
