## L1 بالتفصيل: لماذا ليست `SqliteVecMemoryStore`؟

| القرار | السبب المقاس |
|---|---|
| **لم أستخدم `sqlite-vec`** | ليست مثبتة: `select vec_version()` → `OperationalError`، وبديلها يعني إضافة اعتمادية خارجية إلى مشروع فخره «صفر اعتماديات». أُنجز بـ `sqlite3` القياسي. |
| **تمثيل لفظي لا عصبي** | feature-hashing لـ unigrams+bigrams بأبعاد 512، حتمي عبر الأجهزة. لا نموذج، لا شبكة، لا تكلفة. |
| **حدّه منشور** | `memory/evaluate.py` ينشر: easy set **16/16** (تحقق من التوصيل فقط) · **hard paraphrase 2/16** · false-positive على استعلامات قريبة **0/7**. |
| **البوابة واحدة** | `status == VERIFIED` **و** `hash_matches is True` **و** بصمة SHA-256 موجودة **و** الملف على القرص يطابق البصمة. غير ذلك ⇒ رفض **مسجّل** في `admission_log`. |

### القياس الحي (2026-11-17)

```
كوربس حقيقي (20 تشغيلًا للنواة):   20 مقبول / 0 مرفوض
أرضية الضوضاء p95:                 0.20
recall@3 — Easy (مفردات المستند):  16/16 = 1.000
recall@3 — Hard (صياغات معادِية):  2/16  = 0.125   ← الرقم الصادق
false-positive — غير مرتبط:         0/5   = 0.000
false-positive — قريب (near-miss):  0/7   = 0.000
```

**لماذا نشر 0.125 وليس 1.000؟** لأن مجموعة Easy استخدمت كلمات المستندات نفسها؛
نشرها وحدها سيكون تسويقًا. المجموعة الصعبة هي التي تختبر التعميم، وهي تفشل عند
المرادفات — وهذا مذكور في `memory/README.md` وفي اللوحة نفسها.

### نتائج أخطاء اكتُشفت أثناء البناء (منشورة)

1. **`sqlite3.ProgrammingError` تحت `ThreadingHTTPServer`** — اتصال SQLite مربوط بخيط إنشائه. أُصلح بـ `threading.local()` + قفل كتابة، وأُضيف اختبار تزامن (`test_15`).
2. **اختبار يكشف حدًّا لا ميزة** — `test_11` يفشل إن نجح الاستدعاء على صياغة معادِية؛ إن نجح يومًا فعليك إعادة قياس الأرقام وتحديث الوثائق.
