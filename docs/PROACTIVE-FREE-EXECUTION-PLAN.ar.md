# خطة التشغيل الاستباقي المجاني أولاً — 26 نوفمبر 2026

## القرار

الهدف هو **صفر إنفاق فعلي**، لا شراء خادم أو تفعيل اشتراك تلقائياً. المجاني
ضمن حصص متغيرة وليس ضماناً لتوافر 24/7؛ كهرباء الجهاز والإنترنت وتكلفة استضافته
إن وجدت خارج تكلفة الخدمات البرمجية، ولا يوجد افتراض بأن خادماً مملوكاً بالفعل
بلا تكلفة. لا نفعّل billing أو موارد مدفوعة؛ نختبر السياسة والحصص على الحساب
قبل أي نشر، ونتوقف إذا تعذر إثبات أن التكلفة صفر أو لم يعد المجاني متاحاً.

الأولوية: **تجربة Google Apps Script كمشغّل سحابي دائم بلا خادم** على حساب
المستخدم، بفاصل 30 دقيقة ثم 15 بعد قياس الحصص. توجد الآن تجربة قراءة فقط في [موصل Apps Script](../integrations/apps-script/proactive-watcher/README.ar.md) مع اختبارات محلية؛ لم تُنشر أو تُختبر حياً وليست خدمة مفعّلة. بدائل عند الحاجة:
Vercel Schedules (beta)، ثم جهاز/خادم Linux يملكه المستخدم مع systemd، وGitHub
Actions للمراقبة أو القراءة المؤقتة. لا تُشغّل البدائل على نفس البيانات معاً
بلا قفل موزع؛ في البداية بديل يدوي، وليس failover آلياً.

## الواقع الذي تم التحقق منه

- جدول P0 موجود، وكان هدف P1 مقروءاً عند 0.6؛ التفويض المقروء `proposed`.
  لا نغيّر الهدف ولا نعتبره مكتملاً بالتخمين.
- في `python-2027` يوجد مشغّل قراءة فقط يدوي أو دوري وSQLite محلي اختياري،
  مع قالب خدمة systemd. لا يكتب إلى Sheets أو ينفّذ إجراء، ولم يُتحقق من
  اتصال عملية النشر الحي أو بدء خدمتها. لا توجد هنا بيانات اعتماد Google
  متاحة للعملية. موصلات المحادثة مستقلة عن عملية التشغيل.
- مستودع `ai-2027` عام حسب `gh repo view` وقت الفحص. البحث عن مشروع Vercel
  باسم `ai-2027` في نطاق الحساب أعاد قائمة فارغة؛ مشاريع Supabase المدرجة
  كانت `INACTIVE`. لم ننشئ أو نفعّل أي موارد سحابية.

## تسلسل التنفيذ ومعايير الانتقال

### 0 — شرط الصفر والبيئة

1. تأكيد خطة الحساب وحصصه وقيود المصادقة، دون قراءة قيم أسرار. فشل إثبات
   الصفر أو تجاوز حد مجاني = إيقاف، لا ترقية. سجّل اسم البيئة والحصة فقط.
2. حدد حساب Gmail/تقويم واحداً والنطاق الزمني والموافقة على القراءة. وسوم
   `tainted` و`not_granted` لا تعني أن المحتوى صالح للتعليمات.
3. اختبار وحدة القراءة الحالية دون شبكة ومراجعة عدم تسريب النصوص. **منجز
   محلياً بالاختبارات**؛ لا يعد هذا اتصالاً حيّاً للبيئة المنشورة.

### 1 — دائم وقراءة فقط

1. مراجعة وتثبيت منفّذ Apps Script المُعد ليعمل في حساب المستخدم بصلاحيات قراءة محددة،
   باستخدام بيانات وصفية فقط، وحدّ أحجام/صفحات، وبدون Gmail send أو تعديل
   Calendar أو Sheets. تثبيت trigger كل 30 دقيقة بعد موافقة Google الصريحة.
   إعداد حساب خدمة ليس بديلاً مؤكداً عن موافقة مالك Gmail.
2. لا يتاح نشر Apps Script مباشرة بموصلات المحادثة الحالية؛ يلزم مسار نشر
   معتمد أو قيام المستخدم بإنشاء المشروع ومنح الصلاحيات في Google. لا ندعي
   أن اتصال المحادثة يسمح للـtrigger باستخدامها.
3. اختبار تشغيل يدوي ثم دورتين مجدولتين متتاليتين مع عدادات لا محتوى فيها،
   ومراقبة الأخطاء والحصص وانتهاء التفويض وغياب الدورات. فشل أو شك = توقّف.
   30 دقيقة تعني نظرياً نحو 48 دورة/يوم؛ 90 دقيقة مشتركة على المستخدم تعادل
   متوسط 112.5 ثانية للدورة إذا لم تُستهلك الحصة من سكربتات أخرى، وليس حجزاً
   أو ضماناً. 15 دقيقة تعني 96 دورة و56.25 ثانية في نفس الافتراض.
4. تحديد آلية مستمرة مناسبة وآمنة لتخزين المؤشرات، وقفل واحد لمشغّل واحد؛
   تجربة Apps Script تستخدم `LockService` محلياً لمنع تداخل دوراتها، لكنه ليس
   قفلاً عالمياً بين المشاريع أو المنصات ولم يُختبر حياً. لا نعتمد على SHA
   وحده لإخفاء المعرّفات. اختبر الإعادة
   والحذف وتغيّر الحدث وانقطاع الشبكة وحد الصفحات وتدوير/استرجاع الحالة.

### 2 — جسر Memory P0 بعد استيفاء البوابة

1. تدقيق النظام الفعلي وصيغ checksum والسلسلة الحالية واختبار التوافق؛ لا
   نفترض أن مثال التجزئة أو `inferred` يطابق حقول وقيم الجدول الحالي.
2. منفّذ كتابة واحد مع إعادة قراءة مستقلة، منع الازدواجية عند إعادة المحاولة
   غير المؤكدة، وصلاحيات محددة، ووسوم المصدر؛ Sheets وحده لا يضمن معاملة
   ذرية مشتركة أو منع تعديل السلسلة، ويحتاج تثبيت رأس خارجي موثوق.
3. مرشح خصوصية معتمد قبل المحتوى أو النماذج؛ لا ضمان أن regex يزيل كل
   الحساسية. المهام المستنتجة مسودات للمراجعة مرتبطة بالمصدر، لا أوامر.

### 3 — الحوكمة والإشعارات

منحة نشطة بنطاق وحدود صريحة، ثم موافقة بشرية موثقة مرتبطة بالفعل وبصمته
والهدف والصلاحية والاستخدام الواحد؛ فشل أي تحقق يمنع التنفيذ. لا تعتبر
خلية `approved` وحدها توقيعاً. اختيار قناة تنبيه مجانية وآمنة يُراجع لاحقاً؛
الإشعارات غير موصولة حالياً. محاولات محدودة للأفعال الآمنة القابلة للإعادة
فقط؛ لا إعادة إرسال عمياء لعملية قد تكون نجحت بالفعل.

### 4 — دليل P1 والبدائل

اختبر اتصال العملية الحي، المصدر والتكرار، استمرار الجدولة بعد إعادة النشر،
الإغلاق الافتراضي، عدم تجاوز الحصة/التكلفة، واستعادة الحالة. بعد الأدلة فقط
يُراجع تعديل `pa_goals` و`pa_decisions`. بديل Linux اختياري موثق في
[دليل المشغل](PROACTIVE-WATCHER.md)؛ يتطلب جهازاً يعمل وملف رمز يتجدد بواسطة
مدير أسرار، ولم يتم تثبيت خدمته في هذه البيئة. بناء Vercel وGitHub adapters
منفصلان وغير منفذين الآن، ولا يُطلقان تلقائياً بالتوازي مع الأساسي.
