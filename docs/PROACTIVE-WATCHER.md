# المشغّل الاستباقي للذاكرة P0 — مرحلة قراءة فقط

## الحالة وحدود التنفيذ

أُضيف `python-2027/src/ai2027_protocol/proactive_watcher.py` باستخدام ناقل
`LiveConnectorClient` الموجود. المشغّل **اختياري وغير مفعّل تلقائياً**: يقرأ
معرّفات رسائل صندوق الوارد لآخر 7 أيام وأوقات أحداث التقويم الأساسي للأيام
السبعة القادمة، ويتابع الصفحات بحدود آمنة. لا يقرأ العناوين أو النصوص أو
عناوين البريد أو المرفقات، ولا يستخدم نموذجاً أو يفسر أي محتوى كتعليمات.
كل مصدر مؤقت موسوم `tainted` و`not_granted`. المقترحات المؤقتة للتعارضات
موسومة `open` و`inferred` وترتبط بمصدرين وبـ `dedupe_key` ثابت؛ لا تُحفظ
كمهام حقيقية. الأحداث الملغاة والشفافة لا تُحسب كوقت مشغول، والحدود المتلامسة
ليست تعارضاً. لا تُنشأ مهام من البريد في هذه المرحلة.

الخرج يحوي أعداداً فقط. معرفات المصادر مجزّأة SHA-256 لتوحيد الهوية وليس
كضمان لإخفاء الهوية؛ افتراضياً تبقى بالذاكرة فقط. عند اختيار `--state-db`
تُحفظ المعرفات المشتقة في SQLite محلي خاص مع علامة baseline؛ تحديثها يتم
بمعاملة بعد اكتمال القراءتين، ويمنع تكرار العد حتى بعد إعادة تشغيل العملية.
أول دورة baseline وليست دليلاً على أن الرسائل جديدة فعلياً. اختر `account-scope`
ثابتاً وفريداً لكل حساب؛ هذا اسم يحدده المشغّل وليس تحققاً من حساب Google.
لا يكشف النظام التغييرات على نفس معرّف الحدث، ولا يملك مؤشراً تفاضلياً أو
طابور تسليم دائم. فقدان العملية بعد تسجيل الحالة وقبل طباعة النتيجة قد يفقد
الإشعار؛ SQLite محلي لا يضمن منع التكرار عبر أجهزة متعددة، والبيانات تتراكم
ولا تحذف تلقائياً. يجب تأمين النسخ الاحتياطية وتحديد سياسة احتفاظ وحذف لها.

فشل أي صفحة أو تخطي 10 صفحات/1000 عنصر يرفض الدورة كلها دون تحديث خط الأساس.
إعادة المحاولة محصورة في ثلاث محاولات GET لكل صفحة، دون إعادة محاولة أي كتابة
خارجية. النوافذ والحدود قد تتطلب إعداد مزامنة متينة للإنتاج.

لا توجد كتابة إلى Sheets، ولا إشعارات، ولا تنفيذ خارجي، ولا خدمة مجدولة
مفعّلة تلقائياً، ولا تطبيق لبوابة `pa_delegation_grants` أو `pa_approvals`، ولا
`ssGateway` لاستخراج النصوص. لا يغيّر هذا المشغّل قواعد أو سلطة kernel القائمة.
بسبب تقليل البيانات لا يُدّعى أن حجب الأسرار يغطي كل البيانات الشخصية. ولا
يُحقن سياق نماذج الشخصية في system prompt: البيانات الخارجية غير موثوقة ولا
يجوز منحها سلطة التعليمات. لا نعتبر P1 مكتملة بهذا التغيير.

## التشغيل على جهازك

يحتاج Python 3.11+ وبيئة `python-2027` المثبتة (`pip install -e ./python-2027`)
ورمز OAuth **قصير العمر** في ملف خاص يحدده `GOOGLE_ACCESS_TOKEN_FILE`
أو في `GOOGLE_ACCESS_TOKEN` بصلاحيات قراءة Gmail والتقويم فقط. لا تضع الرمز أو ملفات الاعتماد في المستودع أو سجلات التشغيل.
موصلات Arena في المحادثة لا تمرر رمزها إلى عملية الكود تلقائياً. لا يوجد هنا
تجديد OAuth تلقائي؛ انتهاء الرمز سيؤدي لفشل القراءة ويحتاج تجديداً آمناً من
بيئة النشر. يُعاد فتح ملف الرمز كل دورة، فيمكن لمدير أسرار خارجي تجديده
دون إعادة تشغيل. يلزم أن يكون الملف مطلق المسار، مملوكاً لمستخدم الخدمة
وبصلاحيات 0600 أو أشد، وليس وصلة رمزية. لا تطبع محتواه ولا تضعه في Git. التواريخ اليومية تستخدم المنطقة الزمنية المذكورة لأحداث اليوم الكامل.

```sh
# بعد إعداد GOOGLE_ACCESS_TOKEN خارج المستودع
python -m ai2027_protocol.proactive_watcher --once --calendar-timezone Africa/Cairo
python -m ai2027_protocol.proactive_watcher --interval 900 --calendar-timezone Africa/Cairo
```

الفترة المسموح بها 900–1800 ثانية، وتبدأ بعد نهاية كل دورة؛ تتوقف الجدولة
عند توقف العملية. `--once` يرجع رمز فشل غير صفري إن فشلت القراءة. تفعيل
الحالة الدائمة اختياري، ويتطلب مساراً مطلقاً داخل مجلد خاص مملوك للمستخدم:

```sh
install -d -m 700 "$HOME/.local/state/ai2027" "$HOME/.config/ai2027"
# جهّز رمز قراءة قصير العمر بأمان في ملف خارج Git بصلاحيات 0600.
export GOOGLE_ACCESS_TOKEN_FILE="$HOME/.config/ai2027/google-access-token"
python -m ai2027_protocol.proactive_watcher --once --calendar-timezone Africa/Cairo \
  --state-db "$HOME/.local/state/ai2027/watcher.sqlite" --account-scope primary
```

### إعداد خدمة systemd للمستخدم (اختياري، لم تُفعّل هنا)

على جهاز Linux دائم يعمل عليه systemd للمستخدم، من جذر نسخة المستودع:

```sh
python3 -m venv "$HOME/.local/share/ai2027/venv"
"$HOME/.local/share/ai2027/venv/bin/pip" install -e ./python-2027
install -d -m 700 "$HOME/.local/state/ai2027" "$HOME/.config/ai2027"
install -d -m 700 "$HOME/.config/systemd/user"
install -m 644 deployment/systemd/ai2027-proactive-watcher.service \
  "$HOME/.config/systemd/user/ai2027-proactive-watcher.service"
# قبل التفعيل: ضع ملف الرمز كما سبق، وجدّد الرمز عبر مدير أسرار خارجي.
systemctl --user daemon-reload
systemctl --user enable --now ai2027-proactive-watcher.service
systemctl --user status ai2027-proactive-watcher.service
journalctl --user -u ai2027-proactive-watcher.service -n 20
```

الخدمة تختار المنطقة `Africa/Cairo` واسم الحساب `primary`؛ غيّرهما إذا لم
يناسبا حسابك، واستعمل ملف حالة منفصلاً لكل حساب. استمرار خدمة المستخدم بعد
الخروج يتطلب إعداد مدير الخدمة على جهازك؛ راقب الفشل وانتهاء الرمز. ملفات
السجل تخبرك بالنجاح/الفشل والأعداد فقط، ولا ترسل تنبيهات تلقائياً. التأكد من
دورتين ناجحتين فعلياً وإعادة تشغيل الجهاز مطلوب قبل اعتبار الجدولة حية.

للاختبار دون شبكة:

```sh
python -m pytest -q -o addopts='' python-2027/tests/test_proactive_watcher.py \
  python-2027/tests/test_watcher_state.py
```

## بوابة P1 قبل أي كتابة

الجدول الذي تم التحقق منه لديه أوراق `pa_source_records`, `pa_tasks`,
`pa_approvals`, `pa_delegation_grants`, `pa_audit_logs_202611`؛ السجل الحالي
للمنحة التي فُحصت `proposed` وليس `active`، والهدف يذكر 0.6. لم تُعدّل البيانات.
الجدول يحتوي على 20 ورقة بحسب بيانات التعريف المقروءة، لا 21.

قبل أي تشغيل كتابي أو إعلان 1.0 يلزم على الأقل:

1. التحقق من اتصال **عملية النشر نفسها** وصلاحياتها ونطاق القراءة وموافقة
   المستخدم؛ إكمال مؤشرات مزامنة مستمرة ومراجعة التغييرات والحذف
   والتكرار وإعادة التشغيل وتشغيل نسخة واحدة أو قفل موزع موثوق. حالة SQLite
   المضافة تحفظ بصمات العد فقط وليست بديلاً عن هذه المؤشرات.
2. اعتماد صيغة checksum الفعلية للصفوف الموجودة وحقولها، ولا سيما أن المثال
   المقروء في `pa_tasks` يستخدم `inference` بينما المقترح `inferred`. اختبارات
   تحقق مستقلة وهجرة صريحة قبل تغيير المخطط أو رفع أي صف.
3. توفير بوابة خصوصية معتمدة قبل معالجة المحتوى أو تمريره للنماذج؛ الحجب
   القائم على الأنماط وحده لا يضمن إزالة جميع المعلومات الحساسة أو حقن الأوامر.
4. ربط الكتابة بسلطة kernel والـP1 gate والتحقق من تفويض active وصلاحية
   ونطاق وحدود المنحة؛ طلب موافقة بشرية موثّقة ومربوطة ببصمة الإجراء والهدف
   والصلاحية والاستخدام الواحد، مع إعادة التحقق عند التنفيذ. مجرد تعديل خلية
   `approved` ليس توقيعاً موثوقاً. لا توجد صلاحية تنفيذ في هذا المشغّل.
5. تحديد معيار canonicalization للسلسلة الحالية واختبارها قبل الإضافة؛ سلسلة
   SHA-256 قابلة لكشف التغيير فقط مع تثبيت خارجي موثوق للرأس وليست غير قابلة
   للتلاعب. Google Sheets لا يضمن قفل read-last/append الذري بين كتّاب متعددين؛
   يلزم كاتب واحد مُحكم أو مخزن معاملات/قفل موزع وفحص مستقل. تدوير شهري يجب
   أن يربط آخر رأس بالأول في الشهر التالي. لا نفترض أن خوارزمية المثال تطابق
   السجلات القديمة.
6. بعد الاختبارات الحقيقية وإثبات تشغيل مجدول مستمر فقط، راجع تحديث هدف P1
   وسجل القرار؛ لا ترفع التقدم استناداً إلى اختبارات محاكاة.
