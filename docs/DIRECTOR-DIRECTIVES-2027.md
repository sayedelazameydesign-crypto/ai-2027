# دستور التوجيه — حزمة توجيهات وكيل التنفيذ

**Director Directives & Execution Guardrails — مستودع `ai-2027`**

| البند | القيمة |
|---|---|
| **الجهة المعتمدة** | الموجّه الهندسي (المستخدم) |
| **الجهة الملتزمة** | أي وكيل تنفيذ يعمل على هذا المستودع |
| **الحالة** | ساري — يُقرأ قبل أي مهمة |
| **النطاق** | كل المهام على `sayedelazameydesign-crypto/ai-2027` |

> **قاعدة هذا الملف:** التوجيه عقد تشغيل لا نص استشاري. كل بند فيه إلزامي، وكل مخالفة تُوجب رفض التسليم.

## 0) خط الأساس — قبل أي عمل

شغّل وأبلِغ حرفياً — **لا تفترض حالة، اقرأها**:

```bash
git branch --show-current
git rev-parse --short HEAD
git status --short
git log -n 6 --oneline
```

- أبلِغ بالنتائج **قبل** أن تبدأ أي عمل.
- الشجرة غير نظيفة، أو الفرع غير المستهدف → **توقف وأبلِغ**.
- آخر حالة موثّقة عند كتابة هذا الملف: `fc8cd74` · شجرة نظيفة · محلي = بعيد. **تحقق عليها، لا تعتمدها.**

## 1) المهمة المحددة

كل توجيه يحدد بدقة:

| العنصر | المطلوب |
|---|---|
| **المهمة** | فحص حالة / توثيق / اختبار / تجهيز نشر — بجملة واحدة |
| **النطاق** | الملفات المسموح لمسها (قائمة صريحة) |
| **خارج النطاق** | الملفات الممنوعة (قائمة صريحة) |
| **الحد الزمني** | إن وُجد |

**بلا تحديد نطاق صريح → لا تنفيذ.**

---

## 2) الوصول والمرجعية

- **المستودع متاح للقراءة.** اقرأ الملفات فعلياً؛ لا تفترض محتواها. هذا أهم بند في الملف: أكثر خطأ يقع هو التعليق على ملف لم يُقرأ.
- **المرجع الوحيد:** الملفات الموجودة في بيئة العمل + مخرجات الأوامر في الجلسة الحالية.
- **عنصر أو رابط غير متاح:** اذكره صراحةً. **لا تخمين، لا استنتاج، لا "يفترض أن".**
- **حدود الشبكة:** لا وصول إلا إلى `github.com` · `pypi.org` · `registry.npmjs.org`. أي مورد خارجها = `BLOCKED`.

## 3) القيود الحمراء (لا استثناء)

| # | القيد |
|---|---|
| 1 | **لا تعدّل `projects/` إطلاقاً.** |
| 2 | **لا تُرقِّ** أي عنصر مصنَّف `BLOCKED` أو `PRESENT` أو `DECLARED` ما لم تُستوفَ شروط تنفيذه الفعلية ويُسجَّل مخرَج الأمر. |
| 3 | **لا تدّعِ** نجاح اختبار أو اكتمال رفع أو تعديل ملف ما لم يظهر ذلك نصّاً في مخرجات التنفيذ. |
| 4 | **لا تنفّذ** `commit` / `push` / `merge` تلقائياً. الحفظ قرار الموجّه وحده. |
| 5 | **أي أمر** يحتاج شبكة خارج المسموح أو أداة مدفوعة = `BLOCKED`. أعلنه، لا تتجاوزه. |
| 6 | **لا تحذف** بنداً من ملف معتمد بحجة الاختصار. |

> **قاعدة المجانية (`$0`):** أي مكوّن يتطلب دفعاً للبدء = `BLOCKED` حتى يوجد مسار مجاني. هذه القاعدة تسري على الأدوات وعلى وكلاء التنفيذ أنفسهم.

## 4) شروط التوقف — توقف وأبلِغ، لا تُكمل

توقف فوراً عند أي من:

| # | الحالة | الإجراء |
|---|---|---|
| أ | رقم في المصدر يخالف ما ورد في مسودة أو تقرير سابق | أبلِغ بالمفارقة والملف والسطر |
| ب | مكوّن مصنَّف **أعلى** من الترقية المطلوبة (`PRESENT` ← `PROVEN`) | ارفض الترقية وأعلن التصنيف الحقيقي |
| ج | أمر يتطلب شبكة أوسع أو دفعاً | صنّفه `BLOCKED` وأعلنه |
| د | تعارض بين `git status` والتقرير المكتوب | أبلِغ بالتعارض، لا تُصلح صامتاً |
| هـ | ملف مذكور في تقرير **وغير موجود فعلياً** | أبلِغ باسم الملف وسياق ذكره |

**في كل حالة: أبلِغ بالمفارقة — لا تُصلح صامتاً.** الإصلاح الصامت يُفقد الأثر ويُفسد السجل.

---

## 5) صيغة التسليم — بهذا الترتيب

1. **خط الأساس** — `HEAD` · `status` · آخر الالتزامات (منقولة حرفياً).
2. **ما نُفِّذ فعلاً** — الأمر + المخرَج كما هو.
3. **ما لم يُنفَّذ ولماذا** — `BLOCKED` / مؤجل، بصدق.
4. **التصحيحات** — كل افتراض سقط أثناء التنفيذ.
5. **`git status` بعد العمل** + هل نُفِّذ `commit`؟ (نعم/لا)
6. **خطوة تالية مقترحة واحدة** — بانتظار اعتماد الموجّه.

---

## 6) معايير الرفض التلقائي

يرفض الموجّه أي تسليم يحتوي:

- رقماً **بلا أمر نُفِّذ** خلفه.
- ترقية **بلا مخرَج اختبار**.
- كلمة «يعمل» **بلا نتيجة مسجّلة**.
- حدّاً محجوباً **غير معلن** (`BLOCKED` مخفي).
- تقريراً **لا يذكر `git status`** بعد العمل.
- ادعاء «لا وصول للمستودع» بينما القراءة متاحة.

---

## 7) التصنيفات الخمسة — المرجع الحاكم

| الوسم | المعنى الحرفي |
|---|---|
| `PROVEN` | أمر نُفِّذ في هذه البيئة ونجح، والنتيجة مسجّلة |
| `DECLARED` | الكود/الوثائق موجودة، لكن لم يُنفَّذ الأمر هنا |
| `SIMULATED` | الوضع المُعلن محاكاة صريحة |
| `FAILED` | خلل محدد ومُوثَّق |
| `BLOCKED` | يحتاج ما لا يمكن تشغيله مجاناً/محلياً |

**`PROVEN` لا يعني جاهزية للإنتاج ولا أماناً.** هو يعني سطراً واحداً: نُفِّذ ونجح وسُجِّل.
