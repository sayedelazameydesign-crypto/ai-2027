## لماذا هذا المشروع مهم لمنظومة AI-2027

المشروع يشغّل نموذج Kimi K3 (2.78 تريليون معامل، MoE) على **معالج CPU واحد بـ 8.24GB RAM** عبر بث الخبراء والجذع من القرص بدل إقامتهما في الذاكرة — C99 صرف، بلا BLAS ولا GPU.

### 1️⃣ المسار الاستراتيجي: «عقل محلي مجاني» للوكلاء (Phase 2+)

| المشكلة عندنا | الحل الذي يمثله kimi-k3-in-c |
|---|---|
| وكلاؤنا يعتمدون على مفاتيح API مجانية (Gemini/Groq/OpenRouter) بحصص محدودة | محرك استدلال محلي بلا تكلفة متكررة ولا حصص |
| تجربة الزائر الحية تحتاج backend | نموذج يعمل على جهاز عادي = ديمو محلي كامل بلا سحابة |
| هويتنا «Evidence-First» | مؤلف المشروع يطبق نفس الفلسفة: تحقق bit-identical، قارئ config «يرفض التخمين»، قياس الضوضاء قبل الأرقام |

### 2️⃣ المنهجية التي نتبناها فورًا (بدون نسخ كود)

هذه الدروس تُطبق على **AI Evidence Lab** المخطط:

| منهجية من kimi-k3-in-c | نطبقها في |
|---|---|
| Memory ladder: 12 ميزانية، مخرجات متطابقة بايتيًا عبرها كلها | اختبارات الوكيل تحت سقوف موارد مختلفة (cgroup) مع ثبات القرار |
| قياس الضوضاء أولًا (33% noise floor) قبل أي ادعاء أداء | لا رقم أداء يُنشر دون قياس قابلية التكرار |
| «A test a plausible bug would survive is not a test» | تصميم fixtures في Evidence Lab لتفشل أمام أخطاء محتملة محددة |
| الاعتراف العلني بالحدود («What This Engine Does Not Do») | قسم إلزامي في كل صفحة مشروع |
| السجلات الخام ملتزم بها في المستودع (`certification/`) | موجود أصلًا في 12pro — نعممه |

### 3️⃣ ما لن نفعله (بصدق)

- ❌ **لن ندمج الكود الآن** — مشروع متحرك بسرعة، والإسناد الصحيح هو الإحالة لا النسخ؛ نعيد التقييم عند حاجة فعلية
- ❌ **لن نعلن قدرة K3** في أي مادة تسويقية قبل تشغيلها فعليًا على عتادنا
- ❌ **لا تحميل 1.56TB الآن** — التكلفة/العائد لا يبررها قبل وجود منتج يحتاجها
- ❌ لا نبني GPU path — خارج نطاق «الصفر تكلفة»
