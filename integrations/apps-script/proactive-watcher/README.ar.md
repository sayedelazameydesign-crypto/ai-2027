# موصل Apps Script: تجربة قراءة فقط قبل P1

**الحالة:** كود واختبارات محلية، غير منشور وغير مفعّل ولم يُختبر من Apps Script
حي. لا يستعمل مفاتيح GitHub Actions. يشغّل Google الكود بهوية صاحب الـtrigger
بعد موافقته، ولا يستخدم موصلات Arena للمحادثة. لا حاجة لإرسال أي رمز أو كلمة
مرور. لا نطلب مفتاح Gemini أو بطاقة دفع.

يطلب manifest صلاحية `gmail.readonly` (تسمح تقنياً بقراءة محتوى البريد، رغم أن
الكود يطلب معرفات فقط) و`calendar.events.readonly` و`script.external_request`.
افحص الأذونات المعروضة قبل الموافقة. هناك allowlist لنقطتي Google فقط ولا
توجد صلاحية Sheets أو إرسال بريد أو إنشاء حدث. إعداد script وtrigger تغيير
في إعدادات Google، لكنه لا يكتب في `pa_source_records` أو أي سجل P0.

## خطوة الإعداد على Google (يدوية)

1. افتح [Google Apps Script](https://script.google.com/) بالحساب المطلوب وأنشئ
   **مشروعاً مستقلاً** باسم تختاره. لا تنشره كتطبيق ويب، ولا تشاركه مع الآخرين.
2. الصق محتوى `Code.gs` من هذا المجلد في ملف السكربت واحفظ. من إعدادات المشروع
   فعّل عرض ملف manifest `appsscript.json`، واستبدل محتواه بمحتوى الملف المرفق
   واحفظ. راجع النطاقات وقائمة عناوين الاتصال قبل التنفيذ.
3. يحتاج المشروع السماح باستخدام Gmail API وCalendar API. إذا كانت APIs غير
   مفعّلة، أضف Advanced Services لخدمتي Gmail وCalendar في المحرر لتفعيلهما
   في مشروع Apps Script الافتراضي؛ وإذا كنت تستخدم مشروع Google Cloud قياسياً
   فقد تحتاج تفعيل الـAPIs فيه. لا تربط فوترة أو موارد مدفوعة؛ توقف وراجع إذا
   طُلب منك ذلك. المستخدم مسؤول عن إعدادات الحساب والموافقة. راجع
   [توثيق Google](https://developers.google.com/apps-script/guides/services/advanced).
4. اختر الدالة `watcherPoll` واضغط Run مرة واحدة وامنح الصلاحيات إن أردت. راجع
   Executions: نجاح التجربة يظهر JSON أعدادًا فقط مع `status: "ok"` و`writes: 0`.
   يُسجّل الفشل بشكل عام دون بيانات الرسائل؛ لا ترسل لقطات تحتوي بيانات خاصة.
   **لا تفعّل trigger إذا فشل التشغيل اليدوي أو ظهرت صلاحيات غير متوقعة.**
5. بعد نجاح الاختبار، افتح Triggers > Add Trigger واختر `watcherPoll`، ثم
   Time-driven > Minutes timer > Every 30 minutes واحفظ. تحقق من عدم وجود trigger
   سابق لنفس المهمة. راقب Executions حتى ترى دورتين مجدولتين ناجحتين. للإيقاف،
   احذف الـtrigger من شاشة Triggers؛ ولإلغاء الإذن راجع إعدادات حساب Google.
   إذا ظهر `status: "skipped", reason: "overlap"` فلم تُجرَ قراءة في تلك
   الدورة بسبب تشغيل آخر لنفس المشروع؛ ليست دورة ناجحة، وافحص التكرار والمدة.

يفضل 30 دقيقة أولاً. حصة trigger للحسابات الشخصية 90 دقيقة تشغيل إجمالي/يوم
و6 دقائق لكل تنفيذ، مشتركة مع تشغيلات أخرى وقابلة للتغيير؛ لا يوجد ضمان دائم
أو تكلفة صفر لخدمات أخرى لم يتم التحقق منها. إذا تعطلت الحصة أو الصلاحيات
يتوقف المسار عن النجاح، ويجب فحص Executions/إشعارات Google وإصلاح السبب قبل
إعادة تشغيله. لا يوجد تنبيه تلقائي أو ربط دائم قائم مع `ai-2027` أو Sheets.

## السلوك والحدود

- خلال الذاكرة المؤقتة فقط يقرأ معرفات inbox لآخر 7 أيام، والأحداث المفردة
  للتقويم الأساسي للأيام السبعة المقبلة، عبر GET فقط. لا يجلب نص رسالة أو
  عنوان حدث أو مشاركين أو مرفقات، ولا يطبع معرفات أو قيم الرموز. الأرقام
  تتعامل مع مدخلات خارجية غير موثوقة وليست تعليمات للوكيل.
- يطبع إجمالي المصادر وتعارضات الأحداث **المحددة الوقت**؛ الأحداث الشفافة
  والملغاة ليست وقتًا مشغولاً. يستبعد أحداث اليوم الكامل من فحص التعارض
  ويعدّها في `all_day_excluded` حتى يتم التحقق من المنطقة الزمنية وDST.
  لا تعتبر نتيجة التعارضات قائمة كاملة للمواعيد.
- يستخدم `LockService.getScriptLock()` لمنع التداخل بين تشغيلات **المشروع نفسه**؛
  يتخطى التشغيل المتداخل دون انتظار أو قراءة. ليس قفلاً موزعاً ولا يمنع مشروع
  Apps Script آخر أو Python من قراءة الحساب نفسه. لا ينشئ هذا trigger تلقائياً.
- كل تشغيل baseline مستقل؛ لا حالة دائمة، لا كشف جديد أو تعديل أو حذف، ولا
  dedupe بين الدورات، ولا مهام أو source records دائمة، ولا إشعار فوري، ولا
  مسار تنفيذ أو كتابة خارجي. يختلف ذلك عن SQLite المحلي الاختياري في Python.
- يفحص الأوقات المحددة بصيغة RFC 3339 مع إزاحة معلومة وتواريخ صحيحة؛ الأوقات
  الملتبسة أو غير الصالحة تُفشل الدورة بدلاً من تحويلها تلقائياً.
- حد 10 صفحات و1000 عنصر لكل مصدر و20000 تعارض؛ لا يطبع نجاحاً جزئياً إن
  تعطل أي مصدر أو تجاوز الحدود. حتى ثلاث محاولات GET للأخطاء المؤقتة فقط؛
  يرفض 401/403 دون إعادة محاولة. حد استجابة JSON يفحص الحجم بعد تنزيلها.
- لا تحديث للأهداف أو الموافقات. P1 وإجراءات WRITE تبقى مغلقة حتى الاتصال
  الدائم الفعلي واستيفاء الحوكمة وسلامة السجل والاختبارات المذكورة في
  [خطة التشغيل](../../../docs/PROACTIVE-FREE-EXECUTION-PLAN.ar.md).
