# قارئ أخطاء المستودع المجاني

`repo_doctor.py` أداة محلية للقراءة فقط، تستخدم مكتبة Python القياسية وGit؛ لا تحتاج اشتراكًا أو API مدفوعًا. تفحص الملفات المتعقبة والملفات الجديدة غير المستثناة من Git في جميع مجلدات المستودع. لا تنفذ الكود أو الاختبارات ولا تثبت حزمًا. Python 3.11+ مطلوب لفحص TOML.

```sh
python3 tools/repo_doctor.py --root . --json /tmp/repo-doctor.json
python3 tools/repo_doctor.py --root . --fail-on-findings
python3 -m unittest discover -s tools -p 'test_repo_doctor.py'
```

يحصي التقرير امتدادات الملفات ونطاق التغطية، ويتحقق من صياغة Python وJSON وTOML وXML، ويورد المسار ورقم السطر عندما يكون متاحًا. لا ينسخ محتوى الملفات أو رسائل المحلل التي قد تحتوي على أسرار. الملفات الحساسة الشائعة والروابط الرمزية والملفات الأكبر من 5 MiB متروكة؛ الملفات المستثناة في Git غير مشمولة. عدادات التقرير تبيّن الملفات التي تم فحصها أو تجاوزها. لا تقرأ ملفات اعتماد أو بيانات خاصة رغم الاحتياطات؛ تحقق من التقرير قبل مشاركته لأن أسماء الملفات قد تكشف معلومات.

فحص JSON صارم؛ قد يُبلّغ عن ملفات JSONC الصحيحة مثل `tsconfig` و`devcontainer` بسبب التعليقات أو الفواصل الختامية، لذا راجع النتائج قبل اعتبارها أخطاء. الأنواع الأخرى، بما فيها JavaScript وTypeScript وYAML والملفات الثنائية، **تُحصى فقط** ولا تُفحص صياغتها. هذا ليس فحصًا لكل أنواع الأخطاء ولا يثبت صحة التشغيل أو الأمان أو التوافق مع عام 2027. التشغيلات والاختبارات الفعلية تتطلب أدوات مستقلة ومراجعة بشرية؛ لا توجد ضمانات بعدم وجود أخطاء.

## GitHub Actions (اختياري)

```sh
python3 tools/repo_doctor.py --github-run 45432213264 --json /tmp/repo-doctor.json
```

يتطلب تثبيت `gh` وتسجيل الدخول وصلاحية قراءة التشغيل. يقرأ أسماء الوظائف والخطوات الفاشلة فقط، وليس سجلاتها أو أسبابها الجذرية، ولا يرسل محتويات الملفات. عند تعذر الاتصال يُسجّل الحالة `unavailable` بدل اختلاق سبب. انظر سجلات GitHub Actions للسبب الفعلي. يمكن تشغيل الفحص المحلي دون GitHub.

رمز الخروج الافتراضي 0 حتى عند وجود نتائج؛ استخدم `--fail-on-findings` للحصول على 1 عند وجود خطأ صياغة أو قراءة، و2 عند تعذر سرد الملفات. لا يُعد تعذر GitHub أو الملفات التي لم تُفحص نجاحًا للفحص.
