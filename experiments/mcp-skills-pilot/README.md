# MCP-to-Skill prototype inspired by mcpskills-cli — using stdio transport

**POC ACCEPTED (بوابات موثّقة) — لا يُدمج في `main` الآن؛ اعتماد كتجربة ≠ اعتماد كخدمة أدوات إنتاجية**
**التاريخ:** 2026-11-26 · **الملفات untracked** (تُنشر لاحقاً في Experimental PR مستقل — لا #190)
**تدقيق v1:** `HASH_VERIFIED`/`ARCHIVE_MATCHED` (الأرشيف `545bbe88…b4e25`) · ملاحظات **F-01…F-07 عولجت** في هذه النسخة (v1.1) — بلا أي تغيير على `main` أو #190
**التصحيح المعماري:** هذه التجربة **لم تشغّل `mcpskills-cli` نفسه** (المنشور يتصل بـStreamable HTTP) — طُبّقت فكرته على نقل حزمتنا (**stdio handshake**). الفكرة مستوحاة، التنفيذ محلّي.

> **نطاق المقارنة (صريح):** كل الأرقام أدناه تقيس **تعريفات الأدوات + نص المهارة فقط** — لا تشمل محتوى نتائج الاستدعاءات، ولا بقية سياق النموذج (تعليمات النظام، سجل المحادثة، إلخ). وكلها موسومة **`byte-based estimate`** (قياس حجم نصوص، لا توكنات نموذج فعلية؛ `est = bytes // 4` — tiktoken عُجز لحجب مضيف ملفه).

## 1. الفرضية والمنهج

> تعريفات أدوات MCP تجلس في سياق **كل** turn، بينما المهارة تُحمّل مرة عند الحاجة (Progressive Disclosure).

المؤلف أبلغ عن **75k ← 35k (~53%)** في Cursor — تجربة شخصية بلا قياس مستقل منشور. نحن نختبر الاتجاه بقياس نصوص ساكنة على خوادم **حقيقية من هذا المستودع**، بلا استدعاء نموذج مدفوع.

| عنصر | التفصيل |
|---|---|
| ما قيس فعلاً | `tools/list` حقيقي عبر stdio لخادمين (+ نسخة `--read-only`): `@modelcontextprotocol/server-filesystem@2.4.0` **مثبَّت** + خادمنا `ai2027 mcp` |
| ما بُني فعلاً | **مساران** (أدناه): مهارات مولّدة من الـschemas الحقيقية + `scripts/call.py` (stdlib) |
| ما أُثبت فعلاً | استدعاءات ناجحة متعددة + معاملات خاطئة + أداة غير موجودة + فشل خادم + **رفض الكتابة في نسخة Read-only** |
| ما لم يُفعل | لا Cursor/Claude/نموذج — قياس نصوص ساكن فقط |

## 4. الأرقام (`byte-based estimate`) — تُ reproduce بـ`measure.py`

### (أ) التعريف الدائم — كل turn

| السيناريو | bytes | est توكن* | أدوات |
|---|---:|---:|---:|
| BEFORE: filesystem@2.4.0 (handshake حقيقي) | 19,379 | 4,844 | 16 |
| BEFORE: `ai2027.inspect_file` (handshake حقيقي) | 610 | 152 | 1 |
| **BEFORE الإجمالي — ساكن كل turn** | **19,989** | **4,997** | **17** |
| **AFTER — frontmatter فقط** (مهارة الكتابة) | **335** | **83** | — |
| **RO AFTER — frontmatter فقط** (مهارة القراءة = DEFAULT) | **369** | **92** | — |

→ **−98.3%** (19,989 → 335) للمسار الكامل · **−97.0%** (12,169 → 369) لschemas القراءة وحدها.

### (ب) تحميل المهارة — مرة/جلسة

| البند | bytes |
|---|---:|
| مهارة الكتابة `SKILL.md` (16 أداة) | 8,209 |
| مهارة القراءة `SKILL.md` (10 أدوات) — **أصغر37%** | **5,166** |
| المهارة مقابل schemas خادمها (19,379): **−57.6%** | — |
| جلسة1 turn (كتابة) = 335+8,209 | 8,544 |
| جلسة10 turns (كتابة) = 335×10+8,209 | 11,559 |

### (ج) المقارنة المجمّعة

| طول الجلسة | BEFORE | AFTER (كتابة) | التخفيض |
|---|---:|---:|---:|
| 1 turn | 4,997 | 2,135 | **57.3%** |
| 5 turns | 24,985 | 2,467 | **90.1%** |
| 10 turns | 49,970 | 2,882 | **94.2%** |
| 20 turns | 99,940 | 3,712 | **96.3%** |

**قياس مستقل للمسار Read-only** (الخطوة التالية المطلوبة — منفَّذة):

| RO session | BEFORE (schemas12,169B) | AFTER (369+5,166) | التخفيض |
|---|---:|---:|---:|
| 1 turn | ~3,042 tok | ~1,383 tok | **54.5%** |

→ المسار الافتراضي يوفّر **97.0% ساكناً/turn** مقابل schemas قراءته، **وسطح صلاحيات أصغر بكثير** (0 أداة كتابة مسجّلة).

### جرد الأدوات التدميرية — الصياغة الدقيقة

**No explicit delete tool exposed; destructive filesystem operations still exist.**

| الأداة | السلوك الذي يجب أخذه في الحسبان |
|---|---|
| `write_file` | **يستبدل** محتوى الملف الموجود؛ الكتابة ليست Crash-Atomic |
| `edit_file` | يغيّر المحتوى وقد **لا يكون قابلاً للتكرار الآمن** |
| `append_file` | **إعادة** التنفيذ تُعيد الإضافة (ليس idempotent) |
| `move_file` | **يزيل المصدر** بعد النقل |
| `copy_file` | ينشئ نسخة ولا يستبدل الوجهة الموجودة |
| `create_directory` | إنشاء أو ضمان وجود المجلد |

(لا أداة `delete_file`/`delete_directory` مستقلة — لكن `move_file` يكفي لفقدان المصدر.)

## 6. نتائج الاختبارات (كلها مُشغَّلة اليوم على2.4.0)

| الاختبار | النتيجة |
|---|---|
| قراءة/كتابة خارج الجذر + traversal | `Access denied…` rc=1 (قراءة وكتابة) |
| كتابة داخل الجذر | نجح + تحقّق المحتوى |
| **RO: محاولة `write_file`** | **`Tool write_file not found` rc=1 — الأدوات غير مسجّلة** |
| RO: قراءة ناجحة | `ok:true` rc=0 |
| استدعاءات4 قراءة متعددة | كلها `ok:true` بنتائج حقيقية |
| معاملات خاطئة / أداة مجهولة | validation error / `-32602` — كلاهما rc=1 بلا انهيار |
| فشل الخادم (جذر مفقود) | JSON عام `server failure: the MCP server did not respond` rc=1 + تشخيص stderr محلي + regression ناجح بعده |
| جرد الكتابة | `write_file, edit_file, create_directory, move_file, append_file, copy_file` — **delete: NONE** |
| **F-03:** بوابة الموافقة بلا token | `write approval required … AI2027_SKILL_WRITE_APPROVAL=1` rc=1 — الخادم لا يُستدعى أصلاً |
| **F-03:** بوابة الموافقة بـ`token=1` | كتابة ناجحة داخل الجذر + تحقّق المحتوى · القراءة بلا token تعمل كالمعتاد |
| **F-01:** مهلة initialize (خادم لا يستجيب أبداً) | إرجاع خلال **2.0s** (timeout=1s + shutdown=1s) · stdout عام `server timeout: …` · `ServerTimeout` على stderr محلياً |
| **F-02:** خطأ JSON-RPC يحتوي `/private/workspace/secret.txt` | stdout: `… [redacted-path]` + الكود `-32603` محفوظ (طول100) · الخام كاملاً على stderr |
| **F-02:** نص `isError` يحتوي مساراً | منقّى على stdout · الخام على stderr |
| **F-02:** نص نجاح يحتوي مساراً | **يُمرَّر كما هو BY DESIGN** — read_file يجب أن يعيد المحتوى؛ الادعاء في README مُضيَّق accordingly |
| **F-04:** stderr الخادم | مُورَّث لـstderr المحلي (marker وُجد في fd2) — stdout بقي JSON نقياً |
| **F-07:** بصمة npm حيّة | `check_integrity.py` → **PASS** مقابل `dist.integrity` الكامل من السجل |

## 9. حدود صريحة
